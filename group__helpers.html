Detailed Description

Chat histories, tool definitions, base64 and memory release.

These functions do not use a client: they report errors only through their return value.

Builds the definition of a function tool, the C replacement for passing Python functions as tools.

The result is the JSON object below; add parameters with ollama_tool_add_parameter(). 

{"type": "function", "function": {"name": NAME, "description": DESCRIPTION,
 "parameters": {"type": "object", "properties": {}, "required": []}}}

A single tool can be passed as the tools of a chat request; several tools go in a JSON array built with ollama_json_array() and ollama_json_append().

ollama_json_t *tool = ollama_tool_new("get_weather", "Get the current weather for a city");
ollama_tool_add_parameter(tool, "city", "string", "The name of the city", true);
ollama_chat_request_t req = {.model = "llama3.1", .messages = msgs, .messages_count = n, .tools = tool};
ollama_chat_response_t *res;
if (ollama_chat(client, &req, &res) == OLLAMA_OK) {
for (size_t i = 0; i < res->message.tool_calls_count; i++) {
const ollama_tool_call_t *call = &res->message.tool_calls[i];
const char *city = ollama_json_as_string(ollama_json_get(call->function.arguments, "city"));
// run the tool, then send back the assistant message and
// {.role = "tool", .tool_name = call->function.name, .content = result}
}
ollama_response_free(res);
}
ollama_json_free(tool);

const char *  name,

const char *  description,
bool  required

Adds a parameter to a tool built with ollama_tool_new().

It sets function.parameters.properties[name] to an object with the "type" and "description" given, replacing a parameter with the same name, and adds name to function.parameters.required (once) when required is true. With required false the name is not removed from required: a parameter added earlier as required stays required. It also works on a tool parsed from JSON with the same structure.

ollama_json_t *unit = ollama_tool_add_parameter(tool, "unit", "string", "Temperature unit", false);
ollama_json_t *values = ollama_json_set(unit, "enum", ollama_json_array());
ollama_json_append(values, ollama_json_string("celsius"));
ollama_json_append(values, ollama_json_string("fahrenheit"));

◆ ollama_base64_decode()

unsigned char * ollama_base64_decode ( const char *  text,
size_t *  size 
)

Decodes base64 text, such as the image of an image generation response.

Both the standard and the URL-safe alphabets are accepted, whitespace is ignored and the padding is optional; any other character, or data after the padding, makes the decoding fail. The length is not checked: trailing characters that do not complete a byte are ignored ("Q" decodes to 0 bytes).

Parameters
[in]textthe NUL-terminated base64 text, or NULL
[out]sizereceives the number of decoded bytes, 0 on failure; may be NULL
Returns
The decoded bytes, followed by a NUL byte not counted in size, to release with ollama_free(); NULL if text is NULL or invalid, or if memory runs out.

◆ ollama_free()

void ollama_free ( void *  ptr)

Releases memory returned by the library as a plain buffer.

Use it for the strings of ollama_json_stringify() and ollama_create_blob() and for the results of the base64 helpers. The other objects have their own function: ollama_json_free(), ollama_response_free(), ollama_stream_free(), ollama_messages_free() and ollama_client_free(). Unlike free(), it also works when the library uses another C runtime than the application, as can happen with Windows DLLs.

Parameters
[in]ptrthe memory to release; NULL is ignored
