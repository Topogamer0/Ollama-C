Ollama-C

A C library for Ollama: a port of the official Python library, ollama-python, with the same functions, parameters and behavior, written in portable C99 on top of libcurl.

Documentation: the API reference describes every function, type and field. It is generated from include/ollama.h with Doxygen (cmake --build build --target docs builds it locally in build/docs/html).

#include <ollama.h>
#include <stdio.h>
int main(void) {
ollama_message_t messages[] = {{.role = "user", .content = "Why is the sky blue?"}};
ollama_chat_request_t req = {.model = "gemma3", .messages = messages, .messages_count = 1};
ollama_chat_response_t *res;
if (ollama_chat(NULL, &req, &res) != OLLAMA_OK) {
fprintf(stderr, "error: %s\n", ollama_last_error(NULL)->message);
return 1;
}
printf("%s\n", res->message.content);
ollama_response_free(res);
ollama_cleanup();
return 0;
}

Features

  • Every method of the Python Client: generate, chat, embed, embeddings, pull, push, create, create_blob, list, show, ps, copy, delete, web_search, web_fetch, systemone
  • Streaming (stream=True) through iterators
  • Tool calling, thinking models, structured outputs (JSON schemas), images, logprobs
  • Same configuration as Python: OLLAMA_HOST (with the same host parsing rules; 0.0.0.0 reaches the local server on every platform), OLLAMA_API_KEY, custom headers, timeout
  • Typed responses, plus the full JSON of every response
  • A small JSON API for options, schemas, tool definitions and tool arguments
  • No dependencies besides libcurl; works from C and C++

Any other system with a C99 compiler, CMake 3.14+ and libcurl 7.28+ should work (for example FreeBSD or MinGW), but it is not tested. On Windows, Visual Studio 2019 16.10 or later is needed. The commands below use ctest --test-dir and cmake --install, which need CMake 3.20 and 3.15; with older versions run ctest from the build directory and cmake --build build --target install.

Install with Homebrew

On macOS (Apple Silicon and Intel) and Linux:

brew install topogamer0/tap/ollama-c

This builds and installs the shared library, ollama.h and the CMake and pkg-config files. Use it with find_package(ollama-c) and ollama::ollama, or with pkg-config --cflags --libs ollama-c (no --static needed: Homebrew installs a shared library; on Linux also pass -Wl,-rpath,"$(brew --prefix)/lib" so that the program finds it at run time).

Building

Requirements: a C99 compiler, CMake 3.14+, libcurl with its development headers (libcurl4-openssl-dev on Debian/Ubuntu, libcurl-devel on Fedora, curl on Homebrew, vcpkg on Windows).

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build # optional: runs the tests (needs Python 3 for the fake server)
sudo cmake --install build # installs libollama, ollama.h, CMake and pkg-config files

On Windows, vcpkg installs libcurl from the vcpkg.json manifest:

cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE="$env:VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake"
cmake --build build --config Release
ctest --test-dir build -C Release

With MSVC, compile your own code with /std:c11 or later: in its default mode /W4 warns about the designated initializers used for requests (C4204, C4221), which are standard C99. On Windows the executables of the build (tests and examples) are written to build/bin/<config>, next to the DLLs they need. Models answer in UTF-8: run chcp 65001 in the console before the examples to see accented letters and emoji correctly. File paths (images, blobs) are passed to fopen(), so they are in the active code page, like the arguments of main().

Options: -DBUILD_SHARED_LIBS=ON for a shared library (a DLL on Windows), -DOLLAMA_BUILD_EXAMPLES=OFF, -DOLLAMA_BUILD_TESTS=OFF, -DOLLAMA_WERROR=ON to treat warnings as errors, -DOLLAMA_BUILD_FUZZERS=ON for the libFuzzer targets (Clang only).

Using the library in your project:

# after installing
find_package(ollama-c REQUIRED)
target_link_libraries(my_app PRIVATE ollama::ollama)
# or without installing
add_subdirectory(Ollama-C)
target_link_libraries(my_app PRIVATE ollama::ollama)
cc my_app.c $(pkg-config --cflags --libs --static ollama-c)

Request structs use designated initializers, so you only write the parameters you would pass as keyword arguments in Python; everything left at zero or NULL is not sent.

Passing NULL as the client uses a default client configured from the environment, like the module-level functions ollama.chat(...); ollama_cleanup() releases it.

Usage

Streaming

ollama_stream_t *stream;
if (ollama_chat_stream(client, &req, &stream) == OLLAMA_OK) {

}

Starts a streamed chat (POST /api/chat; Python: chat(..., stream=True)).

There is an iterator per kind of stream: ollama_stream_next_generate, ollama_stream_next_chat and ollama_stream_next_progress (pull, push, create). A part is valid until the next call. HTTP errors such as "model not found" are returned by the *_stream function itself. For chat streams, ollama_stream_message(stream) returns the whole message assembled from the parts (content, thinking and tool calls), ready to be added to the history.

ollama_client_new(NULL) reads OLLAMA_HOST and accepts the same values as the Python client (:8080, example.com/path, https://[::1]:11434, ...). OLLAMA_HOST=0.0.0.0, which makes the server listen on every interface, works on every platform, Windows included: like the ollama command, the client connects to 127.0.0.1 when the host is 0.0.0.0, and to ::1 when it is :: ([::], [::]:8080, https://0.0.0.0:4321, ...). When OLLAMA_API_KEY is set it is sent as Authorization: Bearer ..., which is needed for ollama_web_search, ollama_web_fetch and for using ollama.com as host.

Errors

Every function returns OLLAMA_OK or an error code:

Code Python equivalent
OLLAMA_ERROR_REQUEST RequestError / ValueError (e.g. missing model)
OLLAMA_ERROR_RESPONSE ResponseError, with status_code
OLLAMA_ERROR_CONNECTION ConnectionError ("Failed to connect to Ollama...")
OLLAMA_ERROR_TRANSPORT other httpx errors (timeouts, TLS, ...)
OLLAMA_ERROR_PARSE, OLLAMA_ERROR_IO, OLLAMA_ERROR_MEMORY invalid JSON, unreadable file, out of memory

ollama_last_error(client) gives the message and HTTP status code of the last call.

Memory

  • Requests only borrow the memory they point to.
  • Responses belong to the caller: release them with ollama_response_free(). All their strings, arrays and JSON values live until then.
  • Stream parts belong to the stream.
  • JSON values you create are released with ollama_json_free(); strings returned by the library (ollama_json_stringify, ollama_create_blob, base64 helpers) with ollama_free().

Threads

A client must not be used by several threads at the same time: create one client per thread. The default client (NULL) is not thread-safe. In multi-threaded programs call curl_global_init(CURL_GLOBAL_DEFAULT) once at startup.

Differences from the Python library

  • There is no AsyncClient: run blocking calls on your own threads, with one client per thread.
  • Python functions cannot be passed as tools: use ollama_tool_new() or a JSON schema.
  • Options, formats and other free-form dicts are ollama_json_t values.
  • think and keep_alive are strings ("true", "high", "5m", "-1").
  • Chat streams can assemble the full message for you (ollama_stream_message).
  • An OLLAMA_HOST of 0.0.0.0 or :: connects to 127.0.0.1 or ::1, like the ollama command (Python connects to 0.0.0.0, which fails on Windows, and rejects a bare ::).

Examples

The examples directory mirrors the examples of ollama-python and is built with the library (build/examples/): generate, generate-stream, chat, chat-stream, chat-with-history, tools, structured-outputs, thinking, multimodal, embed, list, show, ps, pull, create, web-search.

ollama pull gemma3
./build/examples/chat-stream

Tests

ctest --test-dir build runs the unit tests and the integration tests, which drive the public API against a fake Ollama server (tests/mock_server.py) and check both the requests sent and the parsing of the answers.

The JSON parser, the response parsers (regular and streaming) and the OLLAMA_HOST parser are fuzzed with libFuzzer, AddressSanitizer and UndefinedBehaviorSanitizer, starting from a corpus of real Ollama responses (fuzz/corpus). The inputs of past crashes are kept in fuzz/regressions and replayed by ctest on every platform:

CC=clang cmake -S . -B build-fuzz -DOLLAMA_BUILD_FUZZERS=ON
cmake --build build-fuzz --target fuzz_json fuzz_host
mkdir -p build-fuzz/corpus # new inputs go to the first directory, the others are only read
./build-fuzz/fuzz/fuzz_json -dict=fuzz/json.dict build-fuzz/corpus fuzz/corpus/json
