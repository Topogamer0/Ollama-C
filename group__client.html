Detailed Description

Connection settings, the default client and error reporting.

A client (Python: ollama.Client) holds the base URL of the server, the headers, the timeout and a reusable libcurl handle. Every API function takes a client as first argument; NULL selects the default client, the equivalent of the module-level functions of the Python library (ollama.chat(...)): it is created on first use with ollama_client_new(NULL), so it reads OLLAMA_HOST and OLLAMA_API_KEY, and it is released by ollama_cleanup(). While it cannot be created, every call that needs it tries again and fails (see ollama_last_error()).

Threads: a client must not be used by several threads at the same time, and the default client is not thread-safe at all: create one client per thread instead. The global initialization of libcurl is not thread-safe either, so multi-threaded programs should call curl_global_init(CURL_GLOBAL_DEFAULT) once at startup, before creating clients.

ollama_client_t *client = ollama_client_new("http://localhost:11434");
ollama_client_set_header(client, "x-some-header", "some-value");
ollama_client_set_timeout(client, 30000);
// ... API calls with client ...
ollama_client_free(client);

◆ ollama_client_new()

ollama_client_t * ollama_client_new ( const char *  host)

Creates a client (Python: ollama.Client(host=...)).

host follows the rules of the Python library. When it is NULL or "", the OLLAMA_HOST environment variable is used instead, and when that is unset or empty too, the local server. The scheme defaults to http; the port defaults to 11434, or to 80 / 443 when an explicit http:// / https:// scheme is given. Tabs and newlines are ignored, the host name is lowercased (up to the zone of a scoped IPv6 address), user information, query and fragment are dropped, and a path is kept without its leading and trailing slashes. Like current Python versions (3.11+), which raise ValueError, the client is not created when the host has unbalanced brackets, data around the brackets, an invalid address between brackets, or a port that is not a number up to

  1. IPvFuture literals ([v1.x]) must use the characters allowed by RFC 3986.

Unlike the Python library, and like the Ollama command-line client, an unspecified address (0.0.0.0 or ::, with or without scheme, port and path) is replaced by the loopback address of the same family (127.0.0.1 or ::1): OLLAMA_HOST=0.0.0.0 makes the server listen on every interface, and connecting to 0.0.0.0 does not work everywhere (it fails on Windows). For the same reason a bare :: is accepted like [::]. For example:

host base URL
NULL or "" (and OLLAMA_HOST unset or "") http://127.0.0.1:11434
"example.com" http://example.com:11434
":8080" http://127.0.0.1:8080
"http://example.com" http://example.com:80
"https://example.com/api/" https://example.com:443/api
"[::1]:11434" http://[::1]:11434
"0.0.0.0" http://127.0.0.1:11434
"https://0.0.0.0:4321" https://127.0.0.1:4321
"[::]:8080" http://[::1]:8080
"::" http://[::1]:11434

If the OLLAMA_API_KEY environment variable is set and not empty, it is sent with every request in an Authorization: Bearer ... header, which ollama_client_set_header() can replace or remove.

Parameters
[in]hostthe address of the server, copied, or NULL to use OLLAMA_HOST
Returns
A new client to release with ollama_client_free(), or NULL, with no error details, if the host (host, or OLLAMA_HOST) is invalid as described above, if OLLAMA_API_KEY contains CR or LF, if memory runs out or if libcurl cannot be initialized.

ollama_status_t ollama_client_set_header ( ollama_client_t *  client,
const char *  name,
const char *  value 
)

Sets a header sent with every request (Python: the headers argument of Client).

Header names are case-insensitive: a header with the same name is replaced. A NULL value removes the header, and "" sends it with an empty value. Setting "Authorization" replaces the header created from OLLAMA_API_KEY. Content-Type, Accept and User-Agent are always set by the library: values given for them are stored but not sent.

Unlike the API calls, this function does not clear the last error of the client when it succeeds.

Parameters
[in,out]clientthe client, or NULL for the default client (created if needed)
[in]namethe header name, copied; it must not be empty or contain ':', CR or LF
[in]valuethe header value, copied; it must not contain CR or LF. NULL removes the header.
Returns
OLLAMA_OK or an error code:
Return values
OLLAMA_OKthe header was set or removed (removing a missing header is not an error)
OLLAMA_ERROR_REQUESTname or value is invalid (the last error says "invalid header"), or client is NULL and the default client cannot be created because OLLAMA_HOST or OLLAMA_API_KEY is invalid
OLLAMA_ERROR_MEMORYout of memory, or client is NULL and the default client cannot be created for another reason

◆ ollama_client_set_timeout()

void ollama_client_set_timeout ( ollama_client_t *  client,
long  timeout_ms 
)

Sets the network timeout of a client (Python: the timeout argument of Client).

Like the httpx timeout of the Python client, it limits the time to connect and the time without receiving any data, not the duration of the whole request; the second limit is applied in whole seconds, rounded up. A blocking call receives nothing until the server is done, so a blocking generation, chat, pull, push or create fails with OLLAMA_ERROR_TRANSPORT when it takes longer than the timeout: use the streaming functions in that case. A call that times out fails with OLLAMA_ERROR_TRANSPORT. The timeout applies to the requests and streams started after this call.

Parameters
[in,out]clientthe client, or NULL for the default client (created if needed; nothing happens if it cannot be)
[in]timeout_msthe timeout in milliseconds. 0 (the default) or a negative value sets no limit, apart from the 300 second connect timeout built into libcurl.

◆ ollama_last_error()

const ollama_error_t * ollama_last_error ( const ollama_client_t *  client)

Returns the details of the last error of a client.

Every API call (the functions of API calls and the *_stream functions of Streaming) clears the error when it starts, so after a successful call the code is OLLAMA_OK and the message "". The errors that happen while the parts of a stream are read are reported by ollama_stream_error() instead.

Parameters
[in]clientthe client, or NULL for the default client. NULL does not create the default client: before its first use the result is a static record with OLLAMA_OK, and when it could not be created, a static record with OLLAMA_ERROR_REQUEST ("invalid OLLAMA_HOST or OLLAMA_API_KEY") or OLLAMA_ERROR_MEMORY ("out of memory").
Returns
The error, never NULL. It belongs to the client: the pointer is valid until the client is released, its message until the next call that uses the client.

◆ ollama_cleanup()

void ollama_cleanup ( void  )

Releases the default client, used when NULL is passed as client.

Call it before exiting, or to make the next call create a new default client, for example after changing OLLAMA_HOST. It is harmless when there is no default client. The pointers returned by ollama_client_host() and ollama_last_error() for the default client become invalid. It does not call curl_global_cleanup().
