Detailed Description

Parameters of the API calls, one struct per method of the Python client.

Fields left at zero / NULL are not sent, so designated initializers only need to mention what the Python call would pass as keyword arguments (the exceptions are noted on the fields):

ollama_generate_request_t req = { .model = "llama3.2", .prompt = "Hi" };

const char * model
Model name, such as "llama3.2"; required.

Requests only borrow the memory they point to, and only during the call: the request is serialized before anything is sent, so a request passed to a *_stream function can be released as soon as that function returns.

Common fields:

  • model is required: NULL or "" fails with OLLAMA_ERROR_REQUEST ("must provide a model").
  • options: JSON object of model options, such as {"temperature": 0}, sent as it is.
  • format: the JSON string "json", or a JSON schema object, for structured outputs.
  • keep_alive: how long the model stays loaded after the call. A string that is a JSON number, such as "300", "0" or "-1", is sent as a number of seconds; any other string, such as "5m", as a duration (Python: keep_alive=300 or ‘keep_alive='5m’). -think: "true" and "false" (case-insensitive) are sent as booleans, any other string, such as the levels "low", "medium" and "high", as it is (Python:think=Trueorthink='high').
  • Arrays come with a_count` field; a count other than 0 with a NULL array fails with OLLAMA_ERROR_REQUEST.
