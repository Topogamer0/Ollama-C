Detailed Description

Iterators over the parts of an answer (Python: stream=True).

The *_stream functions are the equivalent of stream=True. They send the request and wait for the beginning of the answer, so the errors returned by the server before the first part, such as "model not found", are reported by the *_stream function itself, through its status code and ollama_last_error(). They return an iterator over the parts of the answer, read with the ollama_stream_next_*() function that matches the stream:

ollama_stream_t *stream;
if (ollama_chat_stream(client, &req, &stream) == OLLAMA_OK) {
const ollama_chat_response_t *part;
while ((part = ollama_stream_next_chat(stream)) != NULL)
fputs(part->message.content, stdout);
if (ollama_stream_error(stream)->code != OLLAMA_OK)
fprintf(stderr, "error: %s\n", ollama_stream_error(stream)->message);
ollama_stream_free(stream);
} else {
fprintf(stderr, "error: %s\n", ollama_last_error(client)->message);
}

Errors that happen after the first part end the iteration and are reported by ollama_stream_error(). A part belongs to the stream and is valid until the next call on the stream that reads a part, or ollama_stream_free(). Once opened, a stream does not depend on its client, which remains available for other calls.

◆ ollama_stream_next_generate()

const ollama_generate_response_t * ollama_stream_next_generate ( ollama_stream_t *  stream)

Reads the next part of a stream opened with ollama_generate_stream().

It blocks until a part is available. The part belongs to the stream: it is valid until the next call that reads a part of the stream, or ollama_stream_free(), and must not be passed to ollama_response_free().

Parameters
[in,out]streamthe stream; NULL returns NULL
Returns
The part, or NULL at the end of the stream or on error; ollama_stream_error() tells them apart. The errors are OLLAMA_ERROR_PARSE for a line that is not valid JSON, OLLAMA_ERROR_RESPONSE when the server sends an "error" (Python: ResponseError), OLLAMA_ERROR_TRANSPORT or OLLAMA_ERROR_CONNECTION when the transfer fails, OLLAMA_ERROR_MEMORY, and OLLAMA_ERROR_REQUEST when the stream was not opened by ollama_generate_stream(). After an error, every call returns NULL.

◆ ollama_stream_error()

const ollama_error_t * ollama_stream_error ( const ollama_stream_t *  stream)

Returns the error that ended a stream.

Only the errors that happen while the parts are read are reported here; the errors of the *_stream function that opened the stream are reported by ollama_last_error(). The status code of these errors is always -1.

Parameters
[in]streamthe stream, or NULL
Returns
The error, never NULL: its code is OLLAMA_OK while the stream is running and when it ended normally. It belongs to the stream and is valid until ollama_stream_free(). For a NULL stream, a static OLLAMA_ERROR_REQUEST error ("stream is NULL").

◆ ollama_stream_message()

const ollama_message_t * ollama_stream_message ( const ollama_stream_t *  stream)

Returns the message assembled from the parts of a chat stream read so far.

The role is the first one sent by the server ("assistant" before any), the content and the thinking are the concatenation of the fragments (thinking is NULL while there is none), and the tool calls of all the parts are collected; tool_name and images are NULL. Handy to append the answer to the history with ollama_messages_add_message(), even when the stream ended early. When it ended with OLLAMA_ERROR_MEMORY, the message is valid but may miss the last part.

while (ollama_stream_next_chat(stream) != NULL) {}
ollama_messages_add_message(history, ollama_stream_message(stream));
ollama_stream_free(stream);

The current part and the message of ollama_stream_message() are released too. Closing a stream before its end aborts the HTTP request: this is how to stop a generation early.
